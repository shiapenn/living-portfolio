## 1. Overview & Expected Time

Welcome to **The Living Portfolio**. This runbook guides you through taking a fresh clone of the codebase to a fully running, authenticated portfolio and admin workspace.

- **Expected Time:** **Under 15 minutes (< 15 min)**.
- **Outcome:** A running web app on port 4000 serving your personal timeline and knowledge base, with a secured owner admin workspace protected by password and TOTP two-factor authentication.

---

## 2. Prerequisites Checklist

Before beginning, ensure your host environment has the following installed:

- [ ] **Node.js:** v22.x or higher (`node -v`).
- [ ] **pnpm:** v10.x or higher (`pnpm -v`). If needed, enable via `corepack enable`.
- [ ] **Docker & Docker Compose:** Required if using the containerized PostgreSQL + pgvector stack (`docker compose version`). If running with SQLite / in-memory development mode, Docker is optional.
- [ ] **Authenticator App:** An RFC 6238 TOTP-compatible app on your phone or workstation (e.g. Google Authenticator, 1Password, Bitwarden, Apple Keychain, Aegis).

---

## 3. What You Will Need to Hand

Have the following ready before starting the wizard:

1. **Owner Credentials:** A planned master administrator username and a strong passphrase (at least 12 characters).
2. **Authenticator App:** Ready to scan an SVG QR code or import an `otpauth://` seed URI.
3. **Emergency Recovery Storage:** A password manager or secure notes app to paste and save 8 emergency recovery codes (`xxxx-xxxx`).
4. **(Optional) AI Provider API Key:** If enabling automated categorization, answering, or embeddings:
   - Groq Cloud API key (`gsk_...`), or
   - Google Gemini API key (`AIza...`), or
   - Local Ollama endpoint (`http://localhost:11434`), or
   - OpenAI API key (`sk-...`).

## 4. Ordered Step-by-Step Walkthrough

### Step 1: Clone the Repository & Install Dependencies

```bash
git clone https://github.com/shiapenn/living-portfolio.git
cd living-portfolio
pnpm install
pnpm build
```

---

### Step 2: Configure Environment

Copy the default environment configuration:

```bash
cp .env.example .env
```

The default port is **`4000`** and `ENABLE_BUNDLED_WEB=true` is enabled by default, allowing the API process to serve both the HTTP API and the browser web application on a single port.

---

### Step 3: Launch the Runtime

Choose one of two launch modes:

#### Option A: Docker Compose (Recommended for Full Stack)
```bash
docker compose -f docker/docker-compose.hobbyist.yml up -d
```
Verify the health probe returns HTTP 200:
```bash
curl http://localhost:4000/healthz
# {"status":"ok","version":"0.1.0-alpha.0"}
```

#### Option B: Local Node.js Development Mode
```bash
PORT=4000 ENABLE_BUNDLED_WEB=true pnpm --filter @living-portfolio/api dev
```

---

### Step 4: Open the Setup Wizard

Navigate your web browser to:
**`http://localhost:4000/admin/setup`**

*(Note: If you attempt to visit `http://localhost:4000/admin` before setup is complete, you will be automatically redirected to `/admin/setup`.)*

---

### Step 5: Complete the 6-Step Setup Wizard

Follow each step sequentially:

1. **Step 1: Account Creation & Authenticator Enrolment**
   - Enter your chosen administrator username and strong password.
   - Click **Generate Authenticator Secret**. An SVG QR code and `otpauth://` URI will appear.
   - Open your authenticator app, scan the QR code (or copy the text seed).
   - Enter the current 6-digit verification code generated by your app into the confirmation box.
   - Click **Confirm Authenticator & Continue** (this generates your 8 emergency recovery codes).
   - Click the primary **Continue to Credentials** button.

2. **Step 2: Save Emergency Recovery Codes**
   - Copy or download the 8 single-use recovery codes (`xxxx-xxxx`).
   - Store them securely in your password manager.
   - Check the acknowledgement gate: *"I have copied and safely stored all 8 emergency recovery codes"*.
   - Click **Continue to Hosting & Models**.

3. **Step 3: Hosting & Model Configuration**
   - Select your hosting topology preset (Cloud Managed, Self-Hosted VPS, or Local / Private).
   - Enter API keys for your preferred inference and embedding providers (or use local/mock mode).
   - Click **Continue to Notifications**.

4. **Step 4: Notifications (Optional)**
   - Enter an `ntfy.sh` topic or webhook URL for operational escalation alerts, or leave blank to skip.
   - Click **Continue to Backups**.

5. **Step 5: Encrypted Backups (Optional)**
   - Enter a local backup folder path and an `age` recipient public key, or leave blank to skip.
   - Click **Review Configuration**.

6. **Step 6: Review & Launch**
   - Review the summary card showing your configured credentials, hosting preset, and enabled providers.
   - Click **Launch Portfolio** to finalize setup and enter your workspace.

---

### Step 6: Verify Sign-Out and Login

To confirm that your authentication credentials function properly:

1. In the admin workspace, click the **Sign out** button in the top navigation bar.
2. You will be signed out and redirected to **`http://localhost:4000/admin/login`**.
3. Enter your username and password.
4. In the code box, enter the fresh 6-digit code from your authenticator app and submit.
5. You are returned to the Admin Workspace.
6. *(Optional recovery check)*: You can also click the link *"Lost your authenticator device? Sign in with a recovery code"* to authenticate using one of your 8 single-use codes.

---

## 5. Troubleshooting & Deployment Truth

- **Port Truth:** The default application port is **`4000`** (not `3000`). If configuring reverse proxies (Caddy, Nginx, Cloudflare Tunnels), forward traffic to port `4000`.
- **Admin Guarding:** Any direct browser navigation to `/admin`, `/admin/settings`, or `/admin/import` without an active session automatically redirects to `/admin/login` (or `/admin/setup` if the owner account is not yet initialized).
- **Bundled Web Mode:** If deploying API and frontend as a single service, ensure `ENABLE_BUNDLED_WEB=true` is present in your environment.
