## 1. Scope

### 1.1 WP-1.2 Task Objectives & Delivery
- **`[implemented]`** **Centralized `apiClient` Helper (`apps/web/src/renderer.ts`):** Defined and exported `ADMIN_API_CLIENT_SCRIPT`, which encapsulates an authenticated `apiClient` wrapper around `window.fetch`. Automatically inspects `sessionStorage` for `lp_csrf_token` and attaches it via the `X-CSRF-Token` header for state-changing requests, and defaults `Content-Type: application/json`. Embedded in all three admin HTML views (`/admin`, `/admin/login`, `/admin/setup`).
- **`[implemented]`** **Admin Workspace Network Migration (`apps/web/src/renderer.ts`):** Routed all admin workspace actions through `apiClient`: killswitch toggle (`PATCH /api/settings/routing`), initial settings load (`GET /api/settings`), backup drill (`POST /api/settings/backups/run-drill`), redaction preview (`POST /api/entries/redaction-preview`), and L0 entry publish (`POST /api/entries`).
- **`[implemented]`** **Finding `20261020-UX-02` (P0-2) Recovery Messaging & `res.ok` Enforcement (`apps/web/src/renderer.ts`):** Implemented `renderAdminError` returning distinct inline recovery messages:
  - `401 Unauthorized`: `"Your session has expired. Sign in again →"` linking to `/admin/login`.
  - `403 Forbidden`: `"Security check failed (CSRF token invalid or missing). Please refresh and retry."`
  - `500 Internal Server Error`: `"Server error (HTTP ...). Please retry your request."`
  - Network error: `"Network error connecting to server. Please retry."`
  Strictly gated all success UI banners behind `if (res.ok)`, suppressing green confirmations on non-2xx responses.
- **`[implemented]`** **Admin apiClient & Raw Fetch Conformance Test (`apps/api/src/conformance/admin-apiclient.conformance.test.ts`):** Created automated conformance test suite that:
  1. Inspects all inline `<script>` tags across `/admin`, `/admin/login`, and `/admin/setup` and asserts zero occurrences of raw `fetch(` or `window.fetch(` outside the canonical `apiClient` definition.
  2. Executes a negative detector test verifying that simulated raw `fetch` violations throw `[RAW-FETCH-VIOLATION]`.
  3. Verifies `ADMIN_API_CLIENT_SCRIPT` structure, header injection, and `window.apiClient` binding.
  4. Parses every admin inline `<script>` block with `new Function()` to guarantee valid JavaScript syntax without unescaped string or template literal errors.
  5. Asserts the presence of distinct 401, 403, and 500 error recovery HTML markup in `renderAdminWorkspacePage`.
- **`[implemented]`** **Playwright E2E Integration Suite (`tests/e2e/auth.spec.ts`):** Added Test 6 verifying live browser error handling:
  - Forced 401 response displays session expiration banner with sign-in link and suppresses success banner.
  - Forced 403 response displays CSRF security check failure banner and suppresses success banner.
  - Forced 500 response displays server error banner and suppresses success banner.
  - Forced 401 response on redaction preview displays error and suppresses "No confidential secrets" badge.
  - Normal unintercepted request displays success banner only when `res.ok` is true.
- **`[implemented]`** **Landing Mechanism:** Delivered via PR #6 (`feat/wp1.2-admin-api-client`), all PR checks green, and rebase-merged into `main` at `e2156fa060a650179eaafecc668752eb49d118d9` (`e2156fa`).
