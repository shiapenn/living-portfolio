## 6. Runtime Model Provider Governance & Finding `20261021-AI-01` (Instruction 8)

### 6.1 Audit Investigation of Mock Provider Runtime Output
Investigation of `MockModelProvider.complete` in `packages/ai/src/providers/adapters/mock.ts` revealed that unclassified requests returned the following synthetic text:
```text
"Based on the owner's records, this project utilized PostgreSQL with advisory locks to handle concurrency under high load [cite:1]. Matches: PostgreSQL, high load. Not verified: cluster deployment."
```
Because `apps/api/src/app.ts` unconditionally initialized `providers: [mockProvider]`, an unconfigured runtime instance would invoke this mock and produce synthetic statements claiming to represent the owner's records, directly violating the Spec honesty invariant (§1) and degradation requirement (§10.8).

### 6.2 Remediation
1. **Purged Mock Synthesis Claims:** Modified `MockModelProvider.complete` to return a clearly marked simulation string: `[SIMULATED] Mock model synthesis for query [cite:1]...`, ensuring a test mock can never assert claims about the owner's records.
2. **Configuration-Driven Provider Binding:** Updated `createApp()` in [`apps/api/src/app.ts`](../../apps/api/src/app.ts) to resolve model providers strictly from configuration (`cfg.OPENAI_API_KEY`) or explicit options (`options?.providers`).
3. **Spec §10.8 Extractive Degradation:** When no model provider is configured, `providers` is empty (`[]`). `/api/ask` detects the absence of an available provider from the governor and immediately degrades to extractive mode, returning exact excerpts with citations and the mandatory disclosure:
   `"Showing excerpts from the owner's records. Automated answers are paused for now."`
4. **Registration of Finding `20261021-AI-01`:** Logged this defect in [`docs/audits/register.yml`](../../docs/audits/register.yml) as `severity: P1`, `status: fixed`, backed by regression coverage in `apps/api/src/api.test.ts`.
